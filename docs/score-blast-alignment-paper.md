# PDF 원본 악보와 음원 Stem의 BLAST 기반 마디 정렬, 교환 및 채움

**Sorituh(소리터) 악보 정렬 엔진 v4 — 구현 명세 논문**
2026-11-28 · 구현: `web/src/musicxml.ts`, `web/src/score-blast.ts`, `web/src/score-align.ts`, `web/src/score-import.ts`

---

## 초록

사용자가 올린 PDF 악보를 곡의 최종 악보로 쓰되, 악보의 연주 순서와 시간을 실제 음원(Stem)의 흐름에 맞추는 방법을 제안한다. PDF 악보와 실제 연주는 도돌이표, D.C./D.S./Coda, 인트로·아웃트로, 악보에 없는 반복 때문에 마디의 순서와 개수가 다르다. 본 방법은 다음 네 단계로 이루어진다.

1. **악보 펼침(unfolding):** 반복 기호를 모두 해석해 악보를 연주 순서대로 펼친다.
2. **BLAST식 앵커 탐색:** 펼친 마디열과 드럼 박자 격자 위 Stem 마디열 사이에서, 가장 길고 비슷한 구간 하나(앵커)를 찾는다.
3. **연결:** 앵커 앞뒤의 마디를 PDF 순서대로 이어 붙인다.
4. **교환·채움:** 앵커 뒤에서 Stem과 덜 비슷한 마디(70% 미만)는 악보의 다른 마디 중 더 비슷한 것으로 교환하고, 악보가 끝난 뒤에도 남은 음원은 가장 비슷한 악보 마디로 채운다.

모든 음표, 코드, 리듬은 PDF 악보의 것이다. Stem은 위치와 시간을 정하는 비교 데이터로만 쓴다. 실제 곡 두 개에서 다음 결과를 얻었다.

- **Amazing Grace (My Chains Are Gone):** 인쇄된 53마디가 68마디로 펼쳐졌다. 68마디 모두 빈 곳 없이 놓였고, 동기화 구간의 평균 유사도는 77%이다.
- **Our God:** 앵커 뒤 61마디의 평균 유사도가 교환으로 47%에서 81%로 올랐다. 악보 끝 뒤에 남은 26초는 11마디로 채웠다.

## 1. 문제와 원칙

### 1.1 문제

- **입력:**
  - 곡 하나의 PDF 악보 (Harmonic: 피아노/기타 반주와 코드, 또는 베이스 악보, 또는 드럼 악보)
  - 같은 곡의 음원을 나눈 Stem 4개 (vocals, drums, bass, other)
  - 드럼 분석이 준 박자 목록
- **출력:** 곡 시간축 위에 놓인 악보
  - 마디마다 곡의 시작·끝 시각, 원본 PDF의 몇 번째 마디인지, Stem과의 유사도, 상태(동기화, 추정, 교환, 채움)
  - 그 위의 음표(재생용)

### 1.2 설계 원칙

1. **데이터 원천은 PDF다.** 최종 렌더링과 재생에 쓰는 음표, 코드, 리듬, 쉼표는 처음부터 끝까지 PDF 악보의 것이다. Stem에서 뽑은 음표로 대체하지 않는다.
2. **BLAST는 내용을 정하지 않는다.** BLAST는 PDF와 Stem이 가장 길게 일치하는 구간을 찾아 정렬의 기준점을 잡는 데만 쓴다.
3. **PDF 마디를 지우지 않는다.** 매칭되지 않았다는 이유로 마디를 빼지 않는다. 앵커 밖의 마디는 PDF 순서대로 이어 붙이고 '추정'으로 표시해, 동기화가 확인된 구간과 구분한다.
4. **교환과 채움도 PDF의 마디로만 한다.** 앵커 뒤에서 너무 다른 마디를 바꿀 때도, 악보 끝 뒤를 채울 때도 쓰는 것은 같은 PDF의 다른 마디이다(쓰여진 그대로).
5. **앵커는 건드리지 않는다.** 앵커 안의 마디는 유사도가 낮아도 바꾸지 않는다.

## 3. 악보 전처리

### 3.1 MusicXML 읽기

첫 번째 파트의 마디가 악보의 마디이다.

- 마디 길이는 박자표가 정한다: 4분음표 수 = beats × 4 / beat-type.
- 못갖춘마디(첫 마디, 또는 `implicit="yes"`)만 실제 내용 길이를 쓴다.
- 각 음표는 {pitch(MIDI, transpose 반영), start, length (4분음표 단위, 악보 처음부터), measure(마디 번호), part, staff, voice}를 갖는다.
- 붙임줄로 이어진 음은 하나로 합친다.
- 코드 기호(`<harmony>`)는 {start, root, quality, bass, pitchClasses}이다.
- 드럼 음표(`<unpitched>`)는 GM 키, 악기 이름, 줄 위치, 머리 모양(x)으로 kick/snare/tom/hihat/cymbal 중 하나로 정한다.

### 3.2 반복 기호 읽기

마디마다 다음 표시를 모든 파트에서 모은다.

- **도돌이표:** `forward`, `backward`(전체 연주 횟수 `times`, 기본 2)
- **엔딩:** 시작·끝 번호 `endingStart`, `endingStop`
- **길 표시:** 아래 셋 중 하나라도 있으면 표시한다.
  - 기호: `<segno/>`, `<coda/>`
  - 글자(`<words>`): "D.C.", "Da Capo", "D.S.", "Dal Segno", "To Coda", "Coda", "Fine"
  - 소리 속성(`<sound>`): `segno`, `coda`, `tocoda`, `dacapo="yes"`, `dalsegno`, `fine`
- **이름 없는 coda 기호 정리:** "To Coda"인지 Coda 시작인지 표시가 없는 coda 기호는 이렇게 정한다.
  - 명시된 coda가 없으면 마지막 기호를 Coda 시작으로 본다. 단, 이런 기호가 둘 이상이거나 "To Coda"가 따로 있을 때만 그렇다.
  - 그 외의 기호는 "To Coda"로 본다(명시된 To Coda가 없을 때).

### 3.3 엔딩 구간 만들기와 OMR 오류 보정

엔딩은 시작 마디부터 다음 중 먼저 오는 곳까지이다: 끝 표시, 뒤 도돌이표, 다음 엔딩 시작, 앞 도돌이표. 끝 표시가 없거나 반복된 경우도 이 규칙으로 읽는다. 바로 이어서 같은 번호 엔딩이 다시 시작되면 하나로 잇는다.

**OMR 보정 규칙:** 악보 읽기는 엔딩 번호를 자주 틀린다. 그래서 번호보다 구조를 믿는다.
- 뒤 도돌이표로 끝나는 엔딩은 `times`번 중 마지막을 뺀 모든 회차(1..times−1)에 연주한다.
- 그 바로 다음에 붙은 엔딩은 마지막 회차(times)에 연주한다.
- 뒤 도돌이표로 끝나는 엔딩 바로 앞에 붙은, 자기 도돌이표가 없는 엔딩 조각은 그 엔딩의 일부로 합친다.

> 예: Audiveris는 Amazing Grace의 1번 엔딩(28–31마디)을 "28마디 1번 시작/끝, 29마디 2번 시작, 31마디 도돌이표"로 읽었다. 보정 전에는 도돌이표가 2번 엔딩 안에 들어가 반복이 한 번도 실행되지 않았다(53마디 → 50마디). 보정 후에는 1–31, 13–27, 32–53, 68마디로 바르게 펼쳐진다.

### 3.4 악보 펼침 (Score Unfolding)

```
order ← []; start ← 0; pass ← 1; i ← 0; done ← false; back ← false; taken ← {}
segno ← segno가 있는 첫 마디 (없으면 0); coda ← coda가 있는 첫 마디
while i < 마디수 and |order| < 8 × 마디수:
  if back:                                   # D.C./D.S. 뒤의 되돌아감
    e ← i가 속한 엔딩
    if e 있고 e가 그 반복의 마지막 엔딩이 아님: i ← e.끝 + 1; continue
    order.push(i)
    if fine(i): break
    if toCoda(i) and coda > i: i ← coda; continue
    i ← i + 1; continue
  if forward(i) and i ≠ start: start ← i; pass ← 1
  e ← i가 속한 엔딩
  if done and e 없음: pass ← 1; done ← false; start ← i
  if e 있고 pass ∉ e.번호: i ← e.끝 + 1; done ← true; continue
  order.push(i)
  t ← backward(i)
  if t and taken[i] < t − 1: taken[i]++; pass++; i ← start; continue
  if t: done ← true
  if daCapo(i) or dalSegno(i): back ← true; i ← (dalSegno(i) ? segno : 0); continue
  i ← i + 1
```

- **되돌아간 뒤의 규칙:** D.C./D.S.로 되돌아간 뒤에는 반복을 다시 하지 않고, 각 반복의 마지막 엔딩만 연주한다.
- **펼친 악보의 구성:** 펼친 악보는 `order`의 마디를 차례로 이어 붙인 것이다. 음표, 코드, 타격의 시작 위치를 옮기고, `measure`는 펼친 순서의 번호로 바꾼다.
- **원본 참조:** 펼친 각 마디는 원본 PDF 마디의 번호 `printed`(인쇄 순서 0부터)를 갖는다. 이것이 원본과의 참조 관계이다.

## 4. Stem 마디 분석

### 4.1 박자 격자

1. **박자 보정:** 드럼 분석의 박 목록에서 명백한 실수를 고친다. 각 간격을 주변 9개 간격의 중앙값(usual)과 비교한다.
   - 간격이 usual의 1.6배를 넘으면 round(간격/usual)−1개의 박을 고르게 넣는다.
   - 간격이 usual의 0.65배 미만이고 다음 간격과 합쳐 usual에 가까우면(±30%), 가운데 박을 지운다.
2. **박 단위 맞추기:** 드럼 분석이 8분음표나 2분음표를 박으로 셀 수 있다. 악보 4분음표 길이(표시 템포 60/tempo, 없으면 사전 정렬이 찾은 템포)와 박 간격 중앙값의 비율을 {½, 1, 2} 중 가장 가까운 것으로 정한다.
   - 2이면 박을 하나 건너 하나씩 쓴다.
   - ½이면 박 사이에 하나씩 넣는다.
   - 결과는 "4분음표 한 개 = 박 한 개"인 격자이다.
3. **시각 변환:** 박 번호 b(소수 가능)의 시각은 박 사이 선형 보간 `timeAtBeat(beats, b)`로 구한다. 범위 밖은 가장 가까운 박 간격으로 연장하므로 음수나 곡 길이 이후의 시각도 나온다.

### 4.2 스펙트로그램과 특징

1. **스펙트로그램:** 22,050 Hz, hop 512(약 23 ms). 반음당 3행, A0–C8. 대역별 창 크기는 C3 아래 4096, C5 아래 2048, 그 위 1024이다. 레벨은 최댓값 대비 dB(0 ~ −60)이다.
2. **특징 단계:** 2프레임마다 한 단계(약 46 ms)이다.
   - **음이름 크기 loudness[12]:** E1–C7의 각 반음 레벨을 log(1 + 100·10^(dB/20))로 압축한다. 최댓값보다 45 dB 이상 작은 것은 0이다. 이웃 반음보다 크면(피크) 1배, 아니면 0.3배로 더한다. Stem 큰 단계들의 95번째 백분위로 나눠, 큰 소리 ≈ 1, 무음 = 0이 된다.
   - **시작(onset):** C3 이상 행들의 프레임 간 상승량 합(spectral flux)을 중앙값~97번째 백분위 사이로 0~1 정규화한다.
3. **구간 평균:** 각 Stem의 loudness 누적합을 만들어, 임의의 박 구간 [b₀, b₁)의 평균 음이름 크기 `songSlot(stem, b₀, b₁)`을 상수 시간에 구한다.

### 4.3 조성 이동과 파트 배정 (사전 정렬)

악보 전체를 동적 시간 정렬(DTW)로 한 번 곡에 맞춘다(`alignScore`). 이 단계에서 두 가지를 얻는다.

- **조성 이동 `shift`(반음):** 악보가 곡과 다른 조로 쓰였을 수 있다. 전 구간 음이름 분포로 가장 그럴듯한 이동 두 개를 고르고 정렬 비용이 낮은 쪽을 쓴다.
- **파트별 Stem 배정:** 각 악보 파트(staff, voice)를 가장 비슷한 Stem에 배정한다. 선율은 vocals, 낮은음자리표는 bass가 된다. 보컬 선율과 같은 음을 겹쳐 치는 층(60% 이상)도 vocals로 본다.

이후 비교에서는 vocals에 배정된 음표(노래 선율)를 뺀다. 이 정렬의 경로 자체는 마디 배치에 쓰지 않는다.

## 5. 마디–Stem 유사도

곡의 박 b에서 시작해 q박 동안 펼친 악보의 마디 i를 놓았을 때 그 구간 Stem과의 유사도 S(i, b, q) ∈ [0, 1]를 정의한다. **모든 단계(앵커, 연결, 교환, 채움)가 같은 S를 쓴다.** S는 Stem에서 받아 적은 악보가 아니라 그 시간 구간의 **Stem 소리 자체**와 비교한 값이다.

### 5.1 Harmonic / 베이스 악보

- **비교 Stem:**
  - Harmonic 악보는 other와 bass Stem의 합과 비교한다.
  - 베이스 악보는 bass Stem과 비교한다.
- **악보 쪽 (4분음표마다):** 마디의 각 4분음표 칸 k에 대해 12차원 벡터 W_k를 만든다.
  - 음표가 그 칸과 겹치는 길이만큼, (pitch + shift) mod 12 성분에 더한다.
  - 코드 기호가 있으면 그 칸부터 마디 끝까지 코드 구성음 성분에 0.4씩 더한다.
- **Stem 쪽:** H_k = Σ_stem songSlot(stem, b+k, b+k+1).
- **음정 유사도:**
  - P = (1/n) Σ_k c_k, 여기서 n은 W_k와 H_k가 모두 무음인 칸을 뺀 칸 수이다.
  - c_k는 W_k와 H_k가 모두 소리가 있으면 코사인 유사도, 한쪽만 무음이면 0이다. H_k의 합이 0.01 미만이면 무음으로 본다.
- **리듬 유사도:**
  - 16분음표 칸마다, 악보 쪽은 음표가 시작하면 1, Stem 쪽은 그 칸 onset의 최댓값으로 벡터를 만든다.
  - 두 벡터의 코사인이 R이다.
  - 악보 쪽이 비어 있고 Stem onset 합이 1 미만이면 R = 1로 본다.
- **결합:** S = 0.9·P + 0.1·R.

### 5.2 드럼 악보

1. **타격 찾기:** 쓰인 타격마다 Stem 받아쓰기의 같은 16분음표 위치나 ±1칸에서 찾는다.
   - 같은 악기가 있으면 1이다.
   - 비슷한 악기(hihat↔cymbal, tom↔snare)가 있으면 0.5이다.
2. **유사도:**
   - Dice 계수로 구한다: S = 2·Σ찾음 / (쓰인 타격 수 + 들린 타격 수).
   - 쓰인 타격이 없는 마디는 들린 타격 수/8로 감점한다.

## 6. BLAST식 앵커 탐색

### 6.1 대각선

펼친 악보의 마디 i는 악보 처음부터 Q_i개의 4분음표 뒤에서 시작한다. 악보의 첫 4분음표를 곡의 박 d에 놓으면 마디 i는 박 d + Q_i에 놓인다. 하나의 d가 두 서열 사이의 대각선 하나이다(서열 정렬의 diagonal).

- **d의 범위:** −⌈전체 4분음표 수⌉ ≤ d < 박 수.
- **4/4 악보의 제약:** 첫 마디(못갖춘마디 허용)를 뺀 모든 마디가 4박이면, (d + Q₁ − firstBar) mod 4 = 0인 d만 쓴다. 곧 마디 시작이 드럼 격자의 마디선에 온다. 다른 박자의 악보는 모든 d를 쓴다.
- **범위 밖:** 마디가 박 목록 밖(시작 < 0 또는 끝 > 마지막 박)에 놓이면 그 칸의 값은 없음(null)이다.

### 6.2 점수 (치환 행렬)

모든 대각선, 모든 마디의 값 S(i, d + Q_i, q_i)를 모은 집합 A에서 배경 임계값을 정한다.

```
best      = A의 98번째 백분위
threshold = max(0.4, min(A의 75번째 백분위, best − 0.1))
score(i,d) = S(i, d+Q_i, q_i) − threshold
minimum   = 1.6 × (best − threshold)         # 좋은 마디 약 두 개의 몫
```

- 우연 수준으로만 비슷한 마디는 음수가 된다.
- 마디가 모두 비슷한 곡(같은 그루브 반복)이어도 최고값보다 0.1 아래는 양수로 남는다.
- 0.4 미만은 결코 점수를 얻지 못한다.

### 6.3 확장과 선택

각 대각선에서 간격 없는 확장(ungapped extension)으로 점수 합이 가장 큰 연속 구간을 찾는다(Kadane). 앞뒤가 잘 맞으면 중간의 몇 마디가 덜 맞아도 구간 안에 남는다. null 칸은 구간을 끊는다. 악보의 처음이나 끝이 구간에 꼭 포함될 필요는 없다.

```
anchor ← 없음
for d in 대각선:
  total ← 0; from ← 0
  for i in 0..마디수−1:
    if score(i,d) = null: total ← 0; from ← i+1; continue
    if total ≤ 0: total ← 0; from ← i
    total += score(i,d)
    if total ≥ minimum and (anchor 없음 or total > anchor.score
         or (같음 and 더 김) or (같음, 같은 길이, from이 더 앞)):
      anchor ← {d, from, to: i, score: total}
```

- **동점 처리:** 점수가 같으면 긴 쪽, 그다음 악보 앞쪽 마디부터 맞는 쪽을 고른다. 마디가 모두 같은 드럼 악보는 어디에나 맞기 때문이다.
- **앵커가 없을 때:** "악보를 곡에 맞출 수 없음" 오류로 끝낸다.

## 7. 전체 배치: 앵커와 앞뒤 연결

악보 전체를 앵커의 대각선 d 하나에 놓는다. 마디 i는 박 d + Q_i부터 q_i박 동안이고, 시각은 timeAtBeat(d + Q_i)에서 timeAtBeat(d + Q_i + q_i)까지이다.

- **앞부분:** 앵커 앞의 모든 마디는 원래 순서대로, 곡의 앞쪽 박에 놓는다.
- **중간 부분:** 앵커 안의 마디는 Stem과 동기화가 확인된 구간이다.
- **뒷부분:** 앵커 뒤의 모든 마디는 원래 순서대로, 곡의 뒤쪽 박에 놓는다.
- **시간 추정:** 앞뒤 구간의 시간은 인접 박(드럼 격자)의 템포로 추정하며, 박 목록 밖은 가장 가까운 박 간격으로 연장한다.
- **표시:**
  - 앵커 밖 마디: `estimated`
  - 박 목록 밖이라 비교할 수 없는 마디: `outside` (유사도 없음)
- **음표:** 곡 시작 전(음수 시각)에 놓인 음표는 소리로 낼 수 없어 재생 데이터에서만 뺀다. 악보 마디 자체는 남는다.

---

## 8. 앵커 뒤 교환

앵커는 그대로 둔다. 앵커 바로 다음 마디부터 한 마디씩 순서대로 처리한다.

```
후보 ← 인쇄된 마디마다 처음 연주된 것 하나, 길이(4분음표 수)별로 묶음
for i in anchor.to+1 .. 마디수−1:
  if outside(i) or S(i) ≥ 0.70: continue
  b ← 마디 i가 놓인 박; q ← 마디 i의 길이
  j* ← argmax_{j ∈ 후보[q], printed(j) ≠ printed(i)} S(j, b, q)
  if S(j*, b, q) > S(i): 마디 i 자리를 j*의 내용으로 교환
```

- **비교 기준:** 지금 처리하는 마디가 놓인 자리의 Stem과 비교한다.
- **길이 제한:** 같은 길이끼리만 바꾸므로 뒤 마디들의 박은 변하지 않는다.
- **교환:** 교환된 자리는 j*의 음표, 코드, 타격을 쓰여진 그대로 그 자리로 옮겨 쓴다.
- **기록:** 교환된 자리에는 원래 마디와 그 유사도를 `swapped = {number, measure, cost}`로 남긴다.
- **앵커 앞 마디:** 교환하지 않는다.

---

## 9. 악보 끝 뒤 채움

악보의 마지막 마디가 끝난 뒤에도 곡의 박이 남아 있으면, 남은 박을 한 마디씩 채운다.

```
q ← 후보가 가장 많은 길이 (4/4 악보라면 4)
b ← 마지막 마디의 끝 박
while b ≥ 0 and b + q ≤ 마지막 박:
  j* ← argmax_{j ∈ 후보[q]} S(j, b, q)
  if S(j*, b, q) < 0.40: break          # 음악이 끝남
  j*를 쓰여진 그대로 b에 이어 붙임 (estimated, filled)
  b ← b + q
```

악보가 곡보다 길면(마지막 마디가 `outside`) 채우지 않는다.

## 10. 출력

### 10.1 재생 데이터

- **음표:** 놓인 악보(펼침, 교환, 채움 반영)의 음표를 쓰여진 그대로 곡 시간에 놓는다.
  - 음높이는 pitch + shift이고, 세기는 모두 90이다.
  - 시작과 끝은 timeAtBeat(d + 음표 위치)이고, 16분음표 단위(unit)도 함께 둔다.
- **베이스 선(Harmonic 악보에서):** 각 순간의 가장 낮은 음(보컬 파트 제외)을 쓴다. 옥타브는 bass Stem이 실제로 내는 쪽(−12, −24)으로 옮긴다.
- **코드 이름:** 놓인 악보의 음과 코드 기호로 마디마다(바뀌면 반 마디마다) 정해, 곡의 조로 표기한다.
- **드럼 악보:** 놓인 타격을 그대로 곡의 드럼 파트로 쓴다. 곡 시작 전의 타격은 뺀다.

### 10.2 마디 기록 `fromScore.bars[]`

| 필드 | 뜻 |
|---|---|
| `number` | 그 자리에서 연주되는 PDF 마디 번호 |
| `id` | 원본 PDF에서의 순서 번호(같은 번호의 마디 구분) |
| `start`, `end` | 곡 시각(초) |
| `similarity` | 그 자리 Stem과의 유사도 (`outside`이면 없음) |
| `estimated` | 앵커 밖(시간은 인접 박으로 추정) |
| `swapped` | 교환됨: 원래 PDF 마디 `{number, id, similarity}` |
| `filled` | 악보 끝 뒤 채움 |

결과 전체의 유사도는 동기화된 마디(앵커)의 평균이다. 결과에는 엔진 버전 `fromScore.engine`(현재 4)을 기록한다. 화면(믹서, 악보 확인 페이지)은 버전이 다른 결과를 열면 자동으로 다시 만들고, "Regenerate score" 버튼으로 언제든 다시 만들 수 있다.

### 10.3 확인 화면 표기

- **PDF 악보:** 펼친 순서로 그리고, 마디마다 `m.26 66%`처럼 유사도 하나를 붙인다.
  - 앵커 밖: `est.`
  - 교환: `m.27 52% → m.13 85%`
- **곡에 맞춘 악보:**
  - 교환: `m.13 85% (m.27)`
  - 채움: `m.4 84% fill`

**Our God (285초)**
- 펼친 마디는 113마디이다.
- 앵커는 펼친 순서로 처음 52마디(인쇄 번호 1–37)이다(평균 0.82).
- 앵커 뒤 61마디의 평균은 0.47이다. 곡이 이 지점부터 PDF와 다른 순서로 진행되기 때문이다.
- 교환으로 60마디를 바꿔 평균 0.81이 되었다. 70% 미만은 1마디 남았다.
- 악보 끝 뒤 11마디를 채워 283.6초까지 덮었다.

## 13. 한계와 향후 과제

1. **교환은 마디별 탐욕적 선택이다.** 이웃 마디와의 연속성을 보지 않아서, 교환된 마디들이 PDF의 한 구간을 이어서 따라가지 않을 수 있다(예: 후렴 반복에서 11, 40, 69, 63마디가 돌아가며 들어감). 앵커 뒤에서 다음 앵커를 다시 찾는 다중 앵커 방식이나, 교환 후 다음 마디를 교환된 마디의 다음 마디로 잇는 방식이 대안이다.
2. **비교 대상은 Stem 소리의 음이름 에너지이다.** Stem에서 받아 적은 코드와 음표 열과 비교하면 사람이 이해하기 쉬운 근거가 생기지만, 받아쓰기 오류의 영향을 받는다.
3. **앵커는 간격 없는 확장이다.** 드럼 격자에 박이 하나 빠지거나 남는 오류가 보정되지 않으면 앵커가 거기서 끊긴다.
4. **음원 Stem이 PDF 악기 편성과 다르면 유사도 상한이 낮아진다.** 예를 들어 피아노 악보를 기타 Stem과 비교하는 경우이다.
